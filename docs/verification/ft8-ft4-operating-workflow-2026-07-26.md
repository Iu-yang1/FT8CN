# FT8/FT4 呼叫与自动流程验收（2026-07-26）

## 变更边界

- Call 页面只暴露 FT8 和 FT4；Q65 与 EME 控件保留 ID 和实现，但从 Call 页面隐藏，等待阶段 5 的独立 EME 工作台接管。
- `OperatingAutomationController` 在业务层保证同一模式、目标和时隙最多接受一次 early/full/deep 状态跃迁，最多认领一次自动发射。
- 模式、目标、function order 和完整 slot index 在认领时形成快照；FT8/FT4 切换会停止旧会话，Q65 与 experimental 不进入该状态机。
- 本阶段没有修改官方 WSJT-X native 源码、候选预算、pass/round、LDPC/OSD、同步阈值、搜索带宽或频率范围。

## 自动流程测试

新增 6 项确定性 JVM 测试，覆盖：

- early/full 同时隙重复消息只推进一次；
- 同一时隙自动发射只认领一次；
- FT8/FT4 模式或目标不匹配的旧回调不能污染新会话；
- REPLYING → REPORT → ROGER → SIGNOFF → COMPLETE；
- 可配置连续 CQ 上限与退避；生产默认保持原有连续 CQ 行为，不擅自减少发射动作；
- no-reply 去重和用户 stop 幂等。

Debug/Release JVM、Debug/Release APK、lintVital 均通过。真机拉起 `MainActivity` 并进入 Call 页面后，未显示 Q65/EME；模式变化时 UTC、目标、音频频率和发射时序标签立即使用同一当前模式，即使发射序号本身没有变化也不会残留旧的 `[FT4]`/`[FT8]` 前缀。真机切换截图和 logcat 验证未发现 FATAL/ANR。
