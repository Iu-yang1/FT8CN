Against the matching-result pre-optimization baseline, FT8 p95 improved from 719.382 ms to 543.117 ms (24.51%). FT4 p95 improved from 345.682 ms to 269.472 ms (22.04%). Candidate limits, pass/round counts, BP/OSD depth, synchronization thresholds and search bandwidth were not reduced.

O2 and O3 produced identical counts and result hashes, and the pure-noise test produced zero messages. O3 was slower (FT8 p95 1039.436 ms; FT4 p95 563.457 ms), so Release uses `-O2 -DNDEBUG`. Fast-math, native-only CPU flags and LTO remain disabled.

- Strict host build plus CTest, including codec, CRC, LDPC/tone, FT8/FT4 synthetic decode, resampler, scheduler, request snapshots, live/disk state, frequency propagation, Q65 capacity/averaging/TX-RX and OSD equivalence.
- Channel regressions for CFO, DT, deterministic AWGN sweep, overlapping signals and pure noise.
- Java unit tests.
- Android arm64 Debug and Release builds, including the official-core link probe.
- Source-manifest uniqueness, source/tool/flags/patch fingerprints and generated-object collision checks.

## Unavailable or open gates

- No authorized ADB device was present during the final run. APK installation, Android Java-heap/native-allocation capture and device timing were not run.
- An official standalone WSJT-X `jt9` executable was not found, so executable-level cross-oracle testing was not run. The bridge still builds the versioned official vendor sources directly.
- `Q65F_60s_F_60s_12000.wav` was not found. Q65F capacity/generation remains covered only as diagnostic compatibility, not as a formal product mode.
- MSYS2 lacks `libasan` and `libubsan`; the sanitizer configuration was checked and failed explicitly instead of silently passing, but ASan/UBSan execution was unavailable.
- Q65 decode is serial and native parallelism remains disabled. Fortran callbacks and upstream Q65 state are not safe for `PARALLEL_NATIVE`.
- Q65 300-second capture at 24/48 kHz still forms the source-rate Java slot array before direct resampling, and local Q65 playback still holds a complete generated waveform. True streaming 12 kHz capture/playback is therefore not release-verified and remains a memory-risk follow-up; no claim is made that this requirement is complete.
- CI was not added because the Android-capable Flang toolchain is a local custom build without a pinned redistributable package. Local `scripts/verify.ps1` is the mandatory reproducible gate.
